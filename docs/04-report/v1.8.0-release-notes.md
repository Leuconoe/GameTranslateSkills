# GameTranslateSkills v1.8.0

릴리스 산출물을 타이틀 루트의 `_release/`로 옮기고 ZIP 기본 이름을 `<한국어 제목> - <TITLE_ID>.zip`으로
바꾼 minor 릴리스다. 게임 출시일 조사와 릴리스 노트의 출시일·24개월 표시, 게임 레지스트리 점검,
완료 타이틀 정리 규칙도 추가했다.

## 주요 변경

### 릴리스 폴더와 파일명 (NSW·Steam/PC)

- 릴리스 산출물은 `<타이틀 루트>/_release/`(`_work/` 옆)에 둔다. 프로젝트 경계 밖에서 유일하게 쓰기가
  허용되는 위치이며, link/junction이면 실패한다.
- ZIP 기본 이름은 `<한국어 제목> - <BASE_TITLE_ID>.zip`이다(예: `지뢰계 마법소녀 사쿠라 - 01006D202294E000.zip`).
  한국어 제목은 `--korean-title` → 타이틀 루트의 빈 한국어 라벨 폴더 → `PROJECT.md`의 `- Korean title:` 순서로 정하고,
  정할 수 없으면 fail closed. 예전 이름이 필요하면 `--legacy-name`.
- 같은 폴더에 `RELEASE_NOTES.md`, `INSTALL.md`, `SHA256SUMS.txt`, `RELEASE_PACKAGE.json`, `screenshots/`,
  `superseded/`를 둔다. `--replace`로 교체된 ZIP은 지우지 않고 `superseded/`로 옮긴다.
- 예전 `_work/<ID>/60_release/`·`_work/<ID>/40_build/releases/`는 legacy로, 검증기가 경고와 함께 읽기만 한다.
- `project:new`에 `--korean-title`을 추가했다.

### 출시일 조사와 릴리스 노트

- `gt-analyze` 0.2단계: 대상 판(플랫폼·지역)의 최초 출시일을 공식 출처로 확인해
  `PROJECT.md`에 `출시일: YYYY-MM-DD (<플랫폼/지역>, <출처 URL>)`로 기록한다. 확인 못 하면 `unknown`.
- `gt-release` 릴리스 노트(`RELEASE_NOTES.md`)는 사용자용 간소 고정 형식이며, 2번 항목에
  `게임 출시일`을 넣는다. 번역 배포일이 출시일 + 24개월(달력 월)보다 이르면 날짜 뒤에 `*`를 붙인다
  (예: `2025-03-27*`). 배포마다 다시 판정하고, 출시일 미확인이면 `미확인`으로 쓰고 `*`를 붙이지 않는다.
- 릴리스 스크린샷: `_release/screenshots/NN_<what>.png`에 `50_test` 증거에서 복사한 대표 캡처 4~6장.

### 게임 레지스트리와 작업장

- `npm run registry:check`: Title ID 형식·중복, 폴더 존재, 구역/상태 일치, 레지스트리 누락 폴더 점검.
- NSW 타이틀 폴더 이름 규칙 `<English name> [<base TID>][<lang>]`, 한국어 제목은 빈 라벨 하위 폴더.
- `_archive` 구역: 이전 회차 완료 타이틀 보관(`complete` 상태).

### 정리

- 완료 타이틀 최종 정리 절차(`cleanup-contract` §6, `gt-project-cleanup` §5).
- 삭제는 백그라운드 I/O 우선순위 runner 안에서 수행하고, 중지 요청 시 프로세스 트리 전체를 종료·확인한다.

### 스킬 규칙

- 여러 타이틀 병렬 진행, 보류 행이 큐를 막지 않음, 일괄 번역 도우미, 루비 제거, 벡터 폰트 한글 추가,
  엔진 규칙표 기반 한국어 줄바꿈, 조판 우선 이미지 예외, 런타임 공백(NBSP) 점검.

## 검증

- 전체 Node 테스트 100개 통과
- skill bundle contract `Issues: 0`

## 업그레이드 시 주의

- 기본 ZIP 이름과 위치가 바뀌었다. 기존 프로젝트는 다음 릴리스 때 `_release/`로 옮기며, 그 전까지 검증기는
  legacy 위치를 경고와 함께 읽는다. 예전 이름을 유지하려면 `--legacy-name`.
- 기존 릴리스의 `RELEASE_NOTES.md`는 자동으로 바뀌지 않는다. 다음 배포 때 출시일 항목을 채운다.
