# 게임 한글화 작업 안전 규칙 (SAFETY)

> 출처: 실전 한글화 작업 노하우에서 일반화 이식 (2026-08)

이 문서는 특정 게임·플랫폼과 무관하게 모든 한글화 프로젝트(SFC/PS1/PS2/Steam/휴대용 콘솔 등)에 적용하는 안전 규칙이다. 속도보다 원본 보존, 경계 준수, 검증 가능한 증거를 우선한다.

## 1. 프로젝트/타이틀 경계 절대 보호

- 타이틀(프로젝트) 경계는 절대적이다. 다른 타이틀의 폴더가 임시 디렉터리에 보이거나 용량이 크다는 이유만으로 검사·이동·삭제·추출·아카이브·정리하지 않는다.
- 모든 추출·스테이징·패치·릴리스·QA·임시 파일은 해당 타이틀의 작업 디렉터리(`<타이틀 루트>/_work/<프로젝트 ID>` 등 프로젝트가 정한 경로) 아래에만 둔다.
- 작업 중 생성되는 임시 파일·중간 아티팩트·도구 출력도 예외 없이 해당 타이틀의 `_work/<프로젝트 ID>/` 아래에 둔다. 저장소 루트, `$GT_TOOLS`, OS `%TEMP%`, 공용 MCP 현재 디렉터리에는 출력하지 않는다.
- 타이틀 루트는 원본 `.nsp`/`.xci`가 **직접 존재하는 폴더**다. `_title`/`_titles` 같은 컨테이너에 임의의 `title` 폴더를 새로 만들거나, 패키지가 없는 상위 폴더 아래에 작업 환경을 만들지 않는다. 작업 환경은 그 실제 타이틀 루트의 `_work/<프로젝트 ID>/`에만 둔다.
- 삭제 가능한 임시 항목은 `tmp-<단계>-<목적>`, `tmp_<단계>_<목적>` 또는 `*.tmp`로 명명한다. 이름에 `tmp`가 없는 중간 산출물은 만들지 말고, 최종 증거·릴리스·manifest에는 임시 이름을 사용하지 않는다.
- 다른 프로젝트의 프로필, 캐시, 저장 데이터, 로그, 모드 파일은 읽기 전용으로 보존한다. 다른 작업자가 진행 중인 타이틀의 중간 산출물은 그 작업자의 명시적 요청 없이 병합·덮어쓰기·주입·릴리스하지 않는다.
- 작업공간 전체를 대상으로 하는 어떤 작업(정리·커밋·검색 후 일괄 수정)도 프로젝트 경계를 넘지 않는다.

## 2. 정리(cleanup) 규칙

- 삭제·이동 전에 모든 후보를 **정확한 절대경로로 해석**하고, 프로젝트/타이틀 소속, Git 상태, 원본 여부(authoritative source), 확정 릴리스 여부, 복구 가능성을 각각 확인한다.
- `tmp`, `staging`, `cache`, `archive` 같은 폴더·파일 이름은 삭제 승인이 아니다. 이름이 아니라 검증된 정체로 판단한다.
- 정리는 **정확한 allowlist**만 사용한다. 워크스페이스 전역 재귀 정리는 어떤 경우에도 금지한다.
- 후보 목록에 없는 파일은 기본적으로 삭제하지 않고 보고만 한다. 명시적인 prune 옵션이 지정된 경우에만, 정확히 지정된 디렉터리 내부에서만 제거한다.
- 완료 후에는 `gt-project-cleanup` 또는 `npm run project:cleanup -- --project-root "<타이틀 루트>/_work/<프로젝트 ID>"`로 Handoff·PROJECT·WORK_LOG·manifest·세션·QA·release 참조를 추론한 `CLEANUP_PLAN.json`과 `CLEANUP_INSTRUCTIONS.md`를 생성한다. `tmp` 이름은 후보 근거 중 하나일 뿐이며, open evidence·활성/소유권 불명 세션·canonical 산출물은 보존한다. 지시서의 exact 후보를 `approved=true`로 표시하고 현재 plan SHA-256을 함께 넘긴 `--apply --plan`에서만 제거한다. 제거 후 plan hash·경로·개수와 구조 검증 결과를 `WORK_LOG.md`에 남긴다.

## 3. 정션/심링크/reparse point 보호

- 정션, 심볼릭 링크, 마운트 포인트, 기타 reparse point는 보호된 참조로 취급한다.
- 삭제 전에 `LinkType`, `Target`, reparse 속성을 인벤토리로 기록한다.
- 불확실한 트리는 절대 재귀 순회·재귀 삭제하지 않는다. 명시적으로 식별된 **링크 자체**만 제거하거나, 별도로 감사된 링크 없는 하위 항목만 제거하고, 제거 후 링크 대상(target)이 온전한지 확인한다.
- 실행 시험 환경이 타이틀의 작업 트리를 링크로 참조할 수 있다. 패치가 활성 상태인 동안 참조되는 트리를 보존한다.

## 4. 원본·산출물 보존 원칙

- 다음은 사용자의 명시적 승인 없이는 절대 삭제·이동·수정하지 않는다.
  - 원본 게임 패키지/이미지 파일 (ROM, ISO, 설치 패키지 등)
  - 타이틀의 작업 트리(`_work` 등)
  - 실행 시험 환경이 현재 읽고 있는 활성 패치 트리
  - 검증 완료된 릴리스 패키지
  - 사용자가 제공한 번역 소스와 용어집
- 임시 미러(복사본)는 원본 트리의 안전한 대체물이 아니다. 미러가 있다는 이유로 원본을 정리 후보로 삼지 않는다.
- 번역·주입이 불가능한 항목은 빈 값이나 낡은 초안으로 덮지 않는다. `blocked` 상태와 원인, 해제 조건을 기록하고 다음 사이클에서 재검증한다.

## 5. 원자적 패치 주입

- 패치 스테이징·주입은 실행 중인 게임/시험 환경 프로세스와 **독립적**으로 수행한다. 창 포커스, GUI 제어, 다른 실행 세션의 종료를 전제로 하지 않는다.
- 주입 절차:
  1. 실제 주입 대상 루트(사용자 데이터/모드 로드 경로)를 명시적으로 해석한다.
  2. 고유한 타이틀/모드 디렉터리에만 게시한다.
  3. 같은 볼륨의 임시 경로에 먼저 복사하고 SHA-256 등 해시를 확인한다.
  4. 파일 단위 **원자적 rename/replace**로 교체하여, 동시에 실행 중인 프로세스가 기존 파일을 계속 사용할 수 있게 한다.
- 기존 패치(overlay)는 주입 전에 타이틀별 백업을 남긴다.
- 실행 중인 타이틀은 새 패치를 핫리로드하지 않는다. 새로 게시한 패치를 반영하려면 **타이틀 재시작이 필요함**을 기록한다.
- 주입 성공(파일 해시·로그)과 런타임 반영(재시작 후 화면 검증)은 별개의 판정이다. 동시 세션 중에는 보고서에 동시 실행 여부, 스냅샷한 프로세스 정보, `runtime_verified: false`를 기록한다.
- 실행 중인 세션이 같은 타이틀·같은 데이터 루트를 사용하면 그 세션이 열어 둔 기존 모드를 덮어쓰거나 삭제하지 않는다. 새 고유 모드 루트나 격리 데이터 루트에 준비하고, 파괴적 교체는 대상 세션 종료 후에만 수행한다.
- 중간 번역 배치나 빌드 변경마다 실행 시험을 반복하지 않는다. 번역·병합·빌드·정적 무결성 검사·최종 패키징을 먼저 끝내고, 최종 산출물에 대해 실제 입력·확인·저장·다음 화면 시험을 1회 수행하며 로그와 캡처를 보존한다.

## 5-a. canonical 산출물·Eden 세션 중복 방지

- 생성 전 `common/qa-session-rules.md`의 논리 키와 canonical 경로를 확인한다. 같은
  프로젝트·단계·논리 키의 파일이 이미 있으면 크기·해시·manifest를 비교해 exact reuse하고,
  `-1`, `(1)`, 날짜·세션 ID 접미사를 붙인 복사본을 만들지 않는다.
- NSW `eden-mcp` QA는 프로젝트당 `50_test/eden/SESSION.json` 하나와
  `ARTIFACT_MANIFEST.tsv` 하나만 사용한다. 같은 세션 키의 active 세션이 있으면 재사용하고,
  소유권이 증명되는 이전 세션만 정확한 `session_id`로 종료한 뒤 새 세션을 만든다.
- Eden 세션 목록·상태가 local `SESSION.json`과 다르면 새 세션을 생성하지 않고
  `BLOCKED`/`INVALID (cross-session)`로 기록한다. 프로세스 이름·전역 검색으로 다른 세션을
  종료하지 않는다.
- 파일·디렉터리를 만드는 모든 단계는 기존 canonical 경로를 먼저 확인하고, 변경이 필요할
  때만 같은 디렉터리의 `tmp-*` 파일을 원자적으로 교체한다. 세션별 `sessions/`·`runs/` 폴더와
  timestamp 파일을 자동 생성하지 않는다.
- `SESSION.json`이 `pending`이면 remote 응답 유실 가능성을 조사하기 전 새 세션을 만들지
  않는다. `closed` 상태의 `last_session_id`가 있으면 exact remote close와 local close를
  증명한 뒤 `--previous-session-id`로 그 ID를 명시해야 다음 세션을 생성할 수 있다.
- `ARTIFACT_MANIFEST.tsv`의 `artifact_key`와 `path`는 각각 유일해야 한다. 동일 논리 산출물은
  기존 행을 hash/status로 갱신하며, 세션별 로그·캡처 복사본을 계속 쌓지 않는다.

## 6. git 커밋 규칙

- 커밋은 요청된 프로젝트의 **명시적 allowlist**에 있는 파일만 스테이징한다.
- `git add .`, `git add -A`, `git commit -a`는 금지한다. 관련 없는 작업이 dirty 상태일 때 루트 전체 정리·커밋도 금지한다.
- 커밋 전에 staged 파일 이름 목록과 cached diff를 반드시 검사한다.
- 공용 지침·문서를 수정하기 직전에는 파일 해시와 Git 상태를 다시 확인한다. 다른 세션의 갱신이 있으면 최신 내용을 먼저 읽어 병합한 뒤 수정한다.

## 7. PowerShell 경로 취급

- 대괄호(`[`, `]`), 아포스트로피, 비ASCII 문자가 들어간 경로는 `-Path` 대신 반드시 `-LiteralPath`(또는 프로젝트 ID 기반으로 해석된 절대 경로)를 사용한다.
- 와일드카드 확장이나 부분 이름 매칭으로 프로젝트를 선택하게 두지 않는다. 게임 폴더명에는 대괄호·특수문자가 흔하므로, 와일드카드 오인은 잘못된 프로젝트를 대상으로 삼을 수 있다.
- 폴더를 rename한 뒤에는 새 경로 기준의 문서·manifest·보고서만 유효한 것으로 취급하고, 이전 경로를 배치 입력으로 재사용하지 않는다.

## 8. 실행 시험 환경 판정 분리

- 실행 시험 환경(에뮬레이터, 호환 레이어, 실기 등)에 대한 판정은 요소별로 분리해 기록한다: **시험 환경 종류/버전, 펌웨어/런타임, 입력 패키지, 활성 모드 경로, 런타임 판정**을 각각 별도 항목으로 남긴다.
- 원본 환경 기준선(baseline), 수정된 환경 결과, 대체 환경 결과, 실기 결과는 서로 다른 판정으로 유지하며 한쪽 결과로 다른 쪽을 추론하지 않는다.
- 로더의 "패치 적용됨" 로그나 프로세스 생존만으로 성공을 판정하지 않는다. 입력 후 화면이 0 FPS 등으로 고정되면 런타임 실패로 기록하고 화면·CPU·로그를 보존한다.
- 공용 로그 파일은 여러 세션의 기록이 섞일 수 있다. crash/error는 실행 시각·프로세스 ID·명령행이 일치할 때만 해당 시험에 귀속하고, 소유하지 않은 프로세스의 오류는 별도 외부 증거로 기록한다.
- 환경변수만 바꾼 실행이 실제 설정·데이터 경로를 바꾸지 않을 수 있다. 격리 시험은 지원되는 설정 경로 옵션을 사용하고, 시작 로그의 유효 경로를 확인하기 전에는 격리로 표시하지 않는다.
- NSW에서 Eden 또는 Ryubing을 포터블/격리 프로파일로 실행할 때는 에뮬레이터가 실제로 읽는
  시스템 지역을 `한국`/`대한민국`, 시스템 언어를 `한국어`로 고정한다. 호스트 환경변수나
  게임 메뉴 표시만으로 갈음하지 말고 유효 설정·시작 로그와 확인 근거를 기록한다. 확인할
  수 없으면 `PENDING_RUNTIME`으로 남긴다. `eden-mcp`가 사용 가능하면 실행·상태·캡처에
  우선 사용하고, 직접 Eden 실행은 fallback 사유를 기록한다.
- 같은 타이틀에 여러 모드가 겹쳐 적용될 수 있으면, 원인 판정은 단일 모드만 적용된 격리 환경(또는 이전 모드를 읽지 않는 재시작)에서만 확정한다.
- 다른 세션의 실행 시험 환경 프로세스는 종료·일시정지·입력하지 않는다. 종료·입력·화면 캡처는 자신이 시작한 프로세스에만 수행한다.
- 로고 이후 정지나 영상 재생 중 정지가 복수의 환경에서 재현되면, 그 런타임/미디어 실패를 번역·폰트 변경과 분리해 취급한다. 우회책을 추가하거나 동작 중인 언어 패치를 바꾸기 전에 입력 데이터 경로와 환경 로그를 먼저 조사한다.
- 정지 원인 분석은 최소한 「번역 스크립트+폰트」, 「원본 전체」 조합을 같은 환경 조건에서 비교한다. 원본만 정상 진행하면 폰트·이미지보다 스크립트의 특정 레코드(제어 토큰·문자열 길이·인코딩)를 우선 이분 탐색하고, 원본 스크립트로 안전 롤백한 뒤에만 다음 리소스를 시험한다.

## 9. emucap/MCP 런타임 연동

- emucap은 선택적 `gt-qa` 런타임 백엔드다. 번역·추출 단계의 전제 조건으로 설치하거나 NSW 실행시험을 emucap으로 대체하지 않는다.
- 사용 전 [`common/emucap-integration.md`](emucap-integration.md)를 읽고, Control/Tracking MCP의 `bootstrap` 및 현재 `status` capability를 확인한다.
- Tracking 원장은 반드시 현재 프로젝트의 `50_test/emucap/` 아래에 둔다. 기본 Git 루트 `.emucap` 또는 MCP 서버 현재 디렉터리 fallback은 거부한다.
- emucap의 캡처·덤프·세이브스테이트·`output_path`는 프로젝트 내부 절대경로만 사용한다. 원본·공용 도구·플러그인 저장소·활성 모드 원본에는 쓰지 않는다.
- 메모리 쓰기·입력·리셋·상태 로드·미디어 교체는 `log_intervention`으로 명시 기록하고, 에뮬레이터 PASS와 실기 PASS를 별도 판정한다.
- 종료는 emucap이 반환한 현재 `launch_id`로만 수행한다. 프로세스 이름 기반 강제 종료와 타 세션 조작은 금지한다.
