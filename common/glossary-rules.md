# 배치 번역·검수 워크플로우 규칙 (glossary-rules)

> 출처: 실전 한글화 작업 노하우에서 일반화 이식 (2026-08)

이 문서는 게임 텍스트를 배치(chunk)로 나누어 번역·검수하는 표준 절차다. 속도보다 장면 문맥, 인물 말투, 용어 일관성, 엔진 제어 코드 보존을 우선한다. 플랫폼(SFC/PS1/PS2/Steam/휴대용 콘솔 등)과 무관하게 적용한다.

## 1. 시작 조건

번역 시작 전에 프로젝트 작업 폴더에 다음을 준비한다.

- 안정적인 행 ID가 있는 번역 manifest (`translation_manifest.tsv` 등)
- 기준 언어 원문과, 존재할 경우 보조 언어 텍스트
- 화자, 장면 ID, 장면 순서, 원본 파일과 키 또는 오프셋
- 엔진 제어 코드 목록과 줄바꿈 표현
- `30_translation/text/glossary.tsv`와 인물별 말투 메모
- 다른 언어 패치·공식 설정 자료의 출처 기록

기준 언어를 정하지 않은 상태에서 번역을 시작하지 않는다. 첫 번역 타이틀은 전체 주입 전에 (1) 게임이 언어를 어떻게 선택하는지(인게임 메뉴/기기 언어 자동), (2) 실제 사용 가능한 언어 슬롯을 확인하고, 덮어쓸 대상 슬롯 방침을 결정해 프로젝트 문서에 기록한다. 결정 후에는 눈에 띄고 위험이 낮은 문자열 하나만 시험 주입해 선택 슬롯의 실제 소비와 한글 폰트 표시를 확인한 뒤 전체 번역을 진행한다.

인게임 대사·이름·UI·선택지·저장/설정 문구와 한글 폰트가 1순위다. 텍스트/UI가 사용자 화면 검증을 통과하기 전에는 이미지 문구 번역 단계로 넘어가지 않으며, 단계 전환 근거를 작업 로그에 기록한다.

## 2. 기준 언어와 참고 언어

원문이 일본어, 보조가 영어·중국어인 전형적 구성을 기준으로 한다(다른 조합도 같은 원칙).

1. 기준 언어(일본어) 원문을 처음부터 끝까지 읽고 의미를 정한다.
2. 참고 언어(영어·중국어)는 원문이 중의적이거나 생략이 심할 때만 확인한다.
3. 원문과 참고 언어가 충돌하면 원문을 우선하고 충돌 내용을 검수 메모에 남긴다.
4. 참고 언어 문장을 자연스러운 한국어로 옮긴 뒤 원문에 맞추는 역방향 작업은 금지한다.
5. 기존 한국어 초안은 신뢰하지 않는다. 의미 확인은 항상 원문으로 되돌아간다.
6. 다른 언어 슬롯에 주입하더라도 번역의 기준은 항상 원문이다. 해당 슬롯의 텍스트는 주입 대상과 보조 참고 자료로만 쓴다.
7. 기존 검수 완료 번역(`target_ko`)은 안정 ID·키·오프셋이 일치하면 재사용한다. 주입 슬롯 변경만을 이유로 재번역하지 않으며, 빈 대상만 신규 번역 배치에 넣는다.
8. 외부 번역기·타 LLM·온라인 번역 API를 사용하지 않는다. 장면 문맥을 직접 읽고 수동 번역한 결과만 병합한다.

## 3. 배치(chunk) 구성

> **이 절이 번역 배치(chunk) 크기의 canonical 기본 기준이다.** 기본은 80행이며, 타이틀별
> `PROJECT.md`에 근거와 함께 명시된 override가 있을 때만 해당 프로젝트의 모든 배치·검수·manifest에
> 같은 값을 적용한다. override가 없는 다른 문서·스캐폴드 템플릿의 숫자는 따르지 않는다.

- 유효 크기는 `PROJECT.md`의 `batch_size`다. override가 없으면 편집 대상 **80행**, 원문·참고문·초안 합계 48,000자 이하를 적용한다. 전체 잔여분이 유효 batch 미만일 때만 마지막 배치를 잔여 행 수로 구성한다. 40행 override를 사용할 때도 문자 상한·상태·검수·manifest 범위를 프로젝트 문서에 잠근다.
- 장면이 짧으면 여러 장면을 합칠 수 있지만, 화자와 시간대가 크게 바뀌는 장면은 섞지 않는다.
- 장면이 길면 대화 전환이나 사건 단락에서 나눈다. 문장 중간, 선택지 묶음 중간, 회상 전환 직후에는 자르지 않는다.
- 분할 경계에는 앞뒤 **5–10행을 `context_only`로 중복 제공**한다. 이 행은 문맥 확인에만 쓰고 병합 대상에서 제외한다.
- 배치 TSV의 최소 필드: `row_id`, `scene_id`, `text_index`, `speaker`, 원문, 참고문, `current_ko`, `controls`, `context_only`.
- 배치 번호와 행 ID는 재실행해도 바뀌지 않아야 한다.
- 문맥이 복잡한 장면도 편집 대상은 유효 batch 크기를 유지한다. 내부 재독 지점을 더 작게 둘 수는 있으나 별도 배치·병합·빌드 사이클로 분리하지 않는다. 필요하면 `context_only`를 더 제공하고, 마지막 잔여분이 아닌 배치를 임의로 축소하지 않는다.

### 단일 메인 에이전트 chunk 처리

- 번역 산출물 작성에는 서브에이전트·병렬 에이전트를 사용하지 않는다. 메인 에이전트가 유효 batch chunk의 원문 확인, 번역, 윤문, 독립 재독, 구조 검증을 직접 수행한다. 커밋은 chunk마다 하지 않고 최종 누적 단일 커밋 원칙을 따른다.
- 작업 시작 또는 지침·manifest·배치·보고서 수정 직전에 현재 파일과 출력 폴더의 수정 시각·해시, 병합/동기화 보고서를 확인한다. 확인 시점 이후의 변경을 먼저 반영하고 오래된 스냅샷으로 덮어쓰지 않는다.
- chunk마다 고유 `batch_id`와 비중첩 유효 batch 범위를 사용한다. 다음 chunk로 넘어가기 전에는 해당 배치 TSV 작성, 구조 QA, manifest 원자 병합까지만 완료한다. 스테이징, 바이너리 재주입, 카탈로그·폰트 검사, 공식 로그 갱신은 제8절의 누적 빌드 정책에 따라 미룬다.
- 배치별 최소 기록은 재개에 필요한 `batch_id`, 행 범위, QA 결과, manifest 해시로 한정한다. 공식 작업·테스트·검증 로그를 배치마다 갱신하지 않는다.
- 사용자가 지침이나 용어집을 갱신했을 가능성이 있으면 새 chunk 전에 최신 파일을 다시 읽어 작업 조건을 재구성한다.
- 배치 ID가 manifest에 없거나 중복되면 해당 출력을 격리하고 원본 manifest의 전체 ID·source_key와 대조한다. ID 오타를 수동 병합으로 때우지 말고 원자적으로 수정한 뒤 전체 배치의 parse → Review → Merge → Sync를 다시 실행한다.

## 4. 1차 번역·윤문 기준

번역 담당은 스타일 가이드, 용어집, 해당 유효 batch chunk 전체를 읽고 한 번에 한 chunk만 담당하며, 다음 순서로 작업한다.

1. 배치 전체를 읽어 사건, 화자 관계, 감정 변화, 생략된 주어를 파악한다.
2. 반복 고유명사와 도메인 용어를 용어집과 대조한다.
3. 원문 의미를 보존하면서 한국어 어순과 호흡으로 다시 쓴다.
4. 각 행을 앞뒤 행과 이어 읽어 조사, 높임말, 시제, 대명사, 말투를 맞춘다.
5. 새 고유명사, 독음 불확실, 원문·참고문 충돌을 별도 메모로 출력한다.
6. 모든 입력 행을 검토했음을 구조화된 출력의 행 ID 목록(`reviewed_row_ids`)으로 증명한다.

`이라고 하는`, `것이 된다`, 과도한 한자어, 원문식 주어 반복 같은 번역투를 그대로 보존하지 않는다. 짧은 감탄사나 문장 조각도 주변 대사에 맞춰 자연스럽게 연결한다. 표시 문자열에 남는 원어 감탄(가나 등)은 뜻과 호흡을 살린 한국어 감탄으로 옮긴 뒤 잔존 검사를 다시 실행한다.

## 5. 고유명사와 말투 누적 (`glossary.tsv`)

- 새 인명, 지명, 조직, 탈것·장비, 기술 용어는 배치 완료 직후 `30_translation/text/glossary.tsv` 후보표에 추가한다.
- 후보에는 원문, 독음, 한국어안, 분류, 근거 행 ID, 확신도를 기록한다.
- 같은 표기가 인물과 사물(기계 형식 등)을 모두 뜻하면 항목을 분리하고 문맥 판별 규칙을 적는다.
- 인물별 1인칭, 상대 호칭, 존댓말 단계, 어미, 특유 표현은 스타일 가이드에 누적한다.
- 확정되지 않은 표기는 번역 전체에 일괄 치환하지 않는다.

## 6. 구조 검증과 병합 게이트

번역 출력은 기준 TSV에 바로 덮어쓰지 않는다. 먼저 다음을 자동 검사한다.

- 입력 행 ID 전체가 정확히 한 번씩 검토되었는지
- 수정 행 ID가 배치 안에 존재하고 중복되지 않는지
- 자리표시자, 변수, 태그, 링크 키, 색상 코드의 **종류와 개수**
- 리터럴 줄바꿈 문자와 실제 줄바꿈의 혼입
- 루비 처리 정책 위반과 원어 문자(가나·한자 등) 잔존
- 선택지 연결 키, 음성 ID, 파일 경로 같은 비표시 데이터 손상
- 화면 폭, 줄 수, 엔진별 길이 제한

제어 코드·태그·줄바꿈은 번역 전후 **서명(종류+개수)**으로 비교한다. 원어 잔존 검사는 명령행·태그를 제거한 표시 문자열에만 적용한다. 문장부호만 달라진 행은 정책상 허용할 수 있지만 제어 코드 불일치는 항상 거부한다.

검사를 통과한 `high`·`medium` 신뢰도 결과만 1차 후보에 병합한다. `low` 결과와 원문·참고문 충돌 행은 별도 검수표에 남긴다. 거부된 수정은 조용히 초안으로 되돌리지 말고 거부 사유와 제안문을 보존한다.

## 7. 독립 2차 검수

1차 전체 병합 후 독립 재독용 유효 batch chunk 세트를 만든다. 가능하면 1차와 다른 분할 지점을 사용하되 유효 batch 규칙은 유지한다.

- 2차 검수는 1차 결과가 맞다고 가정하지 않고 원문부터 다시 읽는다.
- 참고 언어는 동일하게 보조 자료로만 사용한다.
- 의미 누락, 화자 오인, 관계·시제 오류, 말투 불일치, 용어 흔들림, 번역투를 집중 검사한다.
- 1차와 2차가 의미상 크게 충돌하는 행은 자동 선택하지 않고 충돌 보고서로 보낸다.
- 자주 반복되는 시스템 문구와 선택지는 전체 문자열 기준으로 일관성을 다시 검사한다.
- 용어집 검수는 부분 문자열 단순 포함 검색을 하지 않는다. 짧은 항목이 긴 항목에 포함되는 경우(예: `○○`와 `○○인`) 긴 항목의 원문·번역을 우선하고, 문맥상 올바른 번역을 오탐으로 거부하지 않도록 용어집과 검수 규칙을 먼저 보정한다.
- 용어집 적용 범위는 루비 태그 내부까지 포함한다. 태그 문법은 유지한 채 용어집 한국어형을 넣고, 태그 이름·속성·개수 서명은 별도로 재검증한다.

고품질 완료 판정에는 이 독립 2차 검수가 필수다.

## 8. PDCA 반복

각 사이클은 다음 산출물을 남긴다.

```text
<번역 작업 폴더>/review_cycle_<NN>/
  inputs/
  outputs/
  logs/
  review_manifest.tsv
  reports/
    merge_summary.json
    rejected_revisions.tsv
    low_confidence.tsv
    terminology_conflicts.tsv
    control_validation.tsv
```

검수 보고서의 잔존 원문, 제어 코드 오류, 저신뢰, 용어 충돌을 다음 사이클 입력으로 사용한다. 오류 수가 줄지 않으면 유효 batch 크기는 유지하고 문맥 범위·검수 항목·작업 지시를 보강한 뒤 재실행한다.

### 연속 번역 구간의 누적 빌드·검사 정책

- **연속 번역 구간**은 동일한 타이틀·manifest·주입 규칙으로 여러 유효 batch를 이어서 처리하는 작업 전체를 뜻한다. 대화 turn 종료, 컨텍스트 압축, `continue` 지시, 에이전트 재개만으로 새 구간을 시작하지 않는다.
- 구간 초반에는 최신 안정 스테이징과 깨끗한 원본, 주입 대상 번들, 카탈로그, 폰트, 기준 로그의 존재·크기·해시를 **1회만** 확인한다. 이미 검증된 기준 스테이징은 그대로 재사용하며 같은 내용을 다시 복사·재주입하지 않는다.
- 구간 중간의 각 유효 batch에서는 번역 TSV 작성, 독립 재독, 제어 코드·잔존 원문·ID·중복 검사, manifest 원자 병합까지만 수행한다.
- 스테이징 전체 복사, 깨끗한 번들 재주입, 카탈로그 크기·해시 패치와 검증, 폰트 커버리지·tofu 검사, 파일시스템 diff, 실행 시험, 공식 프로젝트·작업·테스트·검증 로그 갱신은 배치마다 반복하지 않는다.
- 구간 최종에는 누적된 모든 manifest 변경을 깨끗한 원본에 **1회만** 주입해 최종 스테이징을 만들고, 카탈로그와 폰트를 각각 **1회** 검사하며, 누적 결과를 공식 로그에 **1회** 갱신한다.
- 최종점은 전체 번역 대상 소진, 사용자의 명시적 빌드·테스트·릴리스 요청, 또는 소스 구조·주입 규칙이 바뀌는 시점이다. 단순한 진행 보고나 작업 재개는 최종점이 아니다.
- 구조 손상, manifest 충돌, 원본 번들 변경처럼 다음 번역의 안전성을 증명할 수 없는 예외가 생기면 중간 검사를 허용한다. 이 경우 예외 원인과 검사 범위를 기록하되, 정상 배치마다 무거운 빌드 사이클을 반복하는 근거로 삼지 않는다.

## 9. 중단과 재개

- 배치 하나가 완료될 때마다 구조화된 출력과 재개용 최소 QA 상태만 기록한다. 공식 로그는 연속 번역 구간 최종에 누적 1회 갱신한다.
- 메인 에이전트는 현재 chunk 출력 파일의 수정 시각과 검증 상태를 확인하고, 불완전한 chunk는 병합하지 않는다.
- `review_manifest.tsv` 상태는 `pending`, `running`, `complete`, `invalid`, `merged`로 관리한다.
- 재개할 때는 유효한 `complete` 출력을 다시 처리하지 않는다.
- 시간 초과나 실패 배치만 독립적으로 재실행한다.
- 번역은 메인 에이전트가 프로젝트의 유효 batch 크기씩 직렬 처리한다. 서브에이전트는 번역 산출물을 작성하지 않고 최신 지침·문맥·용어·QA·빌드 상태의 읽기 전용 감사만 병렬 수행하며, 감사 결과는 메인 에이전트가 원문부터 재확인한 뒤 채택한다.

## 10. 실패 배치 재실행과 작업 로그

- 각 chunk의 입력 TSV, 원출력, 검증 오류, 재실행 결과를 독립적으로 보존한다.
- `reviewed_row_ids`의 순서·누락·중복 검증에 실패한 배치는 번역문을 수동으로 합치지 말고 해당 배치만 같은 입력으로 재실행한다.
- 성공한 배치의 출력은 재사용하고, 실패 배치가 해결된 뒤에만 manifest를 `complete`로 변경한다.
- 작업 중 발견한 반복 오류는 프롬프트나 스키마를 수정한 이유와 함께 공통 지침의 작업 팁 섹션에 누적한다.
- 로더의 생존 로그·패치 적용 로그는 프로세스 생존만 증명한다. UI 이미지/폰트가 별도 아카이브에 있거나 한글 글리프가 없을 수 있으므로, 원본과 패치본의 A/B 로그를 비교하고 실제 화면에서 입력·메뉴·시나리오를 확인하기 전에는 런타임 정상 또는 정지 원인을 확정하지 않는다.

## 11. 실전 구조·chunk 작업 팁

- **다국어 이식판**은 별도 작업 폴더를 사용한다. 원판에서 완료된 행을 exact-context 동기화로 먼저 이식하고, 원문이 없거나 문맥이 실제로 다른 행만 수동 번역한다. 판본 간 배치 파일과 manifest를 섞지 않으며 `rejected_control_mismatch: 0`을 동기화 게이트로 둔다.
- 각 chunk는 임시 파일에 완전히 쓴 뒤 **원자적 rename/replace**하고, 파일이 완성되기 전에는 Review/Merge를 실행하지 않는다. 전역 Merge는 한 개의 잘린 출력 파일 때문에 전체가 실패할 수 있다.
- **단일 행 ID 오타도 전역 Merge를 실패**시킬 수 있다. 오류가 난 배치만 원본 manifest와 대조해 고친 뒤, 전체 배치의 파싱과 Review/Merge/Sync를 재검수하고 오류 0을 확인한다.
- 엔진별 배치 스키마의 안정 행 필드명은 미리 확정한다(예: 정수 `segment` vs `segment_id`). 원본 파일명과 행 식별자를 manifest와 대조한 뒤 병합하고, 스키마 필드가 없으면 매핑을 중단하고 해당 배치만 수정한다.
- 슬롯 대응이 필요한 UI 리소스는 소스 언어 슬롯→대상 언어 슬롯의 인덱스 대응을 먼저 만든다. 번역 대상 필드만 바꾸고 분기/속성/명령/변수는 보존한 뒤, 깨끗한 export → staged import → re-export 왕복을 수행한다. 대상 밖 diff 0건, 대상 mismatch 0건, 레코드 수 일치를 통과해야 주입 후보로 인정한다.
- 커스텀 아카이브의 문자열은 사람이 추정한 오프셋을 쓰지 말고 실제 인코딩 바이트 검색으로 위치를 재확인한다. 동일 길이 치환이 성공해도 가변 길이 치환의 재배치/인덱스 규칙이나 런타임 안전성은 증명되지 않는다. 길이 필드, 재배치, 인덱스, 전체 재검색, 실행 확인을 모두 통과하기 전에는 `blocked`로 둔다.
- 표준 추출 도구가 실패하면 대체 도구·검증된 fallback 스크립트를 시도하되, 추출 결과는 원본과 경로 집합·파일 수·총 바이트·파일별 해시를 전수 대조해 `동일/변경/추가/삭제` 건수로 검증한다. 종료 코드 0이나 추출 성공만으로 후속 안전성을 증명하지 않고 후속 게이트를 유지한다.
- 루비·제어 토큰은 뜻이 같아 보이는 번역어로 바꾸지 말고 **원문 glyph 전체를 비교**한다. 원어·한글 혼합 태그가 발견되면 해당 배치를 Review에서 격리하고 원문 태그와 재대조한 뒤에만 Merge한다. 닫힘 토큰까지 포함한 서명을 보존한다(예: `$[표시문$/독음$]` 형식이면 여닫는 토큰 모두 유지).
- 대형 스크래치 JSON은 최상위 래퍼 키(`rows` 등)를 먼저 확인한 뒤 행 배열을 읽는다. 입력을 바로 리스트로 가정하면 인덱스가 래퍼 키에 적용되어 중단될 수 있으므로, 출력 전 원문 `id`·`source_key`·원문 텍스트를 다시 대조한다.
- 셸·도구 출력을 중간 전달물로 써서 패치 파일을 만들 때는 한 호출의 출력 한도를 넘기지 않도록 범위를 나눈다. 출력 생략 표지(`tokens truncated`, 말줄임표)가 파일에 섞일 수 있으므로, 각 조각 적용 직후 파싱, 예상 행 수·연속 ID, 원본 `source_key`·원문 일치를 검사하고 통과 전에는 번역·Review·Merge를 진행하지 않는다.
- 폰트·아카이브 도구는 종료 코드만으로 성공/실패를 판정하지 않는다. 출력 파일 존재·크기·해시를 함께 확인한다. 슬롯 ID 기반 교체 도구는 표시용 ID와 실제 인덱스가 다를 수 있으므로 교체 전후 목록의 인덱스·오프셋·길이를 비교하고, 목표 슬롯을 추출해 원본·패치 해시를 일치시킨다.
- 이미지 import는 정확히 대응하는 원본 리소스를 기준으로 하고, import 후 extract→export 왕복으로 크기·해상도·알파·해시를 검증한다. 여러 장면이 든 아카이브는 실제 이름 목록을 먼저 고정하고 전체 대상 수의 왕복 검증 `hash_failures=0`을 확인한다. 한두 장만 검증해 전체를 증명한 것으로 간주하지 않는다.
- 릴리스 압축 파일은 프로젝트가 정한 **canonical 이름 하나만** 사용한다(예: `<빌드 폴더>/releases/<프로젝트 ID>.zip`). 게임명·날짜·언어·버전·구성요소 접두사/접미사를 붙이지 않고, 중간 ZIP은 만들지 말고 폴더/보고서로 보존하며, 런타임·파일 목록·해시 검증이 끝난 뒤 canonical ZIP 하나만 원자적으로 생성한다.
- 번역·주입이 불가능한 행은 빈 번역이나 낡은 초안으로 덮지 않는다. `blocked`와 차단 원인, 해제 조건을 기록하고 다음 PDCA 사이클에서 재검증한다.

## 12. 읽기 전용 서브에이전트 동시 작업 게이트

- 서브에이전트의 읽기 전용 감사/준비를 병렬 실행하기 전에 다음 4가지를 점검한다.
  1. 공용 지침 파일의 갱신 여부
  2. 대상 프로젝트의 `PROJECT.md`, `WORK_LOG.md`, 번역 manifest의 최근 수정 시각/해시
  3. 관련 번역 산출물의 `git status --short` 결과
  4. 진행 중인 review/manifest 상태(`pending/running/invalid/merged` 등)
- 점검은 5초 이내에 끝낼 수 있어야 하며, 갱신이 있으면 즉시 반영하고 이어서 chunk를 시작한다.
- 서브에이전트는 `프로젝트 | 감사범위 | 입력파일 | 현재 단계 | 다음 액션` 형식으로 10초마다 상태를 한 줄 보고한다.
- heartbeat가 2회 이상 누락되면 해당 에이전트의 진행 chunk를 중단하고 중앙에서 상태 점검 후 재할당한다.
- 서브에이전트는 번역 폴더, manifest, 용어집, 작업 로그, 공용 지침을 수정·스테이징·커밋하지 않는다. 번역 JSON/TSV 작성과 Merge/Sync 실행도 금지한다.
- 메인 에이전트는 서브에이전트의 읽기 전용 감사가 끝난 뒤 지침·manifest·대상 배치의 해시와 `git status --short`를 다시 확인하고, 한 번에 한 유효 batch chunk만 작성한다.
- 공용 지침을 수정하기 직전에는 파일 해시와 Git 상태를 다시 확인한다. 다른 세션의 갱신이 있으면 최신 내용을 먼저 읽어 병합하고, 변경 후 재독·엄격 검증을 수행한 뒤 최종 누적 커밋 범위에 포함한다.

## 13. 완료 조건

- 모든 번역 대상 행이 1차와 독립 2차 검수를 통과함
- 저신뢰와 거부 수정이 0건이거나 사람이 승인한 예외 목록에 있음
- 제어 코드, 링크, 줄바꿈, 자리표시자 검증 오류 0건
- 용어집과 인물 말투 규칙이 최종 TSV에 일관되게 적용됨
- 원문 언어 잔존이 의도된 고유명사·연출 외에는 없음
- 초기 확인 결과, 선택한 덮어쓰기 슬롯과 실제 소비 근거가 프로젝트 문서에 기록됨
- 깨끗한 원본 바이너리에 최종 TSV를 한 번만 주입함
- 시험 주입에서 선택 슬롯과 한글 폰트 표시를 확인하고, 실행 환경에서 시나리오, 선택지, 백로그, 저장·불러오기, 설정과 엔딩 경로를 확인함
