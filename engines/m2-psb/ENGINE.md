# M2 엔진 노하우 — PSB/MDF 아카이브 · scn 시나리오 · Squirrel UI · PSB 폰트

> 출처: 실전 한글화 작업에서 일반화 (2026-11)
> 근거 타이틀: M2 이식 ADV 2건(NSW, 일본어 원본). 텍스트·폰트는 bench 검증까지 확인했고, 한글 표시는 런타임 미검증이다.
> 엔진 분석이 이뤄질 때마다 이 문서를 보강한다.

## 대상 엔진

M2가 Switch로 이식한 ADV 계열. emote/PSB 데이터 포맷을 쓰며 KiriKiri Z 계열 PSB와 일부 구조를 공유한다.

- **식별 서명**: RomFS에 `*_info.psb.m` + `*_body.bin` 아카이브 쌍, 시나리오 `*.txt.scn.m`(PSB), UI 스크립트 `*.nut.m`(Squirrel2),
  `config/language.psb.m`(언어 슬롯 목록), `config/init.psb`(fontList)가 있다.
- **MDF 래핑**: `.m` 파일은 MDF(zlib + XOR)로 감싸여 있다. XOR 키는 ExeFS에서 찾으며, 프로젝트 `90_tools/environment/`에 키 파일로 두고
  커밋·배포하지 않는다.
- **언어 슬롯**: `language.psb.m`의 슬롯(예: jp/en/tw/cn)을 보고 정한다. ko 슬롯이 없으면 기본은 `jp` 텍스트 제자리 교체다.

## 도구

공용 도구가 없으므로 프로젝트 `90_tools/scripts/`에 Python 파서를 둔다. 같은 엔진의 다른 타이틀 도구를 재사용할 때는 그대로 복사하고
SHA-256을 기록하며, 모듈 이름이 겹치면 이름을 바꿔 둔다(예: 읽기 전용 `psb.py`와 쓰기 가능한 PSB writer를 `m2psb.py`로 분리).

| 역할 | 내용 |
|---|---|
| 아카이브 | `*_info.psb.m` 인덱스 + `*_body.bin` 본체 해제·재구성 |
| MDF | zlib + XOR 해제·재래핑 |
| 텍스트 | scn(PSB) 대사·선택지·제목, Squirrel `nut` 문자열, systext 추출·주입·재추출 검증 |
| 폰트 | PSB v4 비트맵 폰트(`textfont*.psb.m`)와 raw TTF(`*.ttf.m`) 덤프·빌드·검증 |

## 핵심 원칙

1. **번역 전 identity 왕복**: 원문 그대로 주입한 빌드를 재추출해 모든 행이 일치해야 한다(무수정 round trip).
2. **행마다 개행 표현을 보존한다.** scn 대사는 엔진 이스케이프 `\n` 문자열을 쓰지만 systext·nut 일부 행은 실제 개행 문자를 쓴다.
   일괄 도구가 하나로 정규화하면 재추출 검증에서 불일치가 난다.
3. **재추출 검증 스캐너는 원문 언어로 행을 거르지 않는다.** nut·systext를 일본어 포함 여부로 골라 읽으면 번역된 행이 "누락"으로 보인다.
4. 폰트는 RomFS의 폰트 아카이브(`font_body.bin` 등)에만 있을 수 있다. 패치 아카이브에 폰트 override가 있는지 먼저 확인한다.
5. **업데이트 패치 아카이브(`patch_info.psb.m`)에 새 키를 추가하지 않는다.** 원래 없던 키(예: `image/<이름>`)를
   하나라도 넣으면, 바이트가 원본 그대로여도 부팅이 첫 Now Loading에서 멈춘다. Eden 로그에는 `Unmapped Read8`가
   반복된다. 기존 키의 교체와 base 아카이브(motion·image 등)의 재빌드는 정상이다. 패치에 없는 항목을 바꿔야 하면
   해당 base 아카이브를 다시 빌드한다. base 이미지 아카이브는 GB 단위라 배포본이 커진다. 빌드 뒤에는 패치 키 집합이
   원본 업데이트와 같은지 검사한다.

## 폰트 (한글 주입)

- **consumer 확인**: `config/init.psb`의 fontList와 `init.nut`의 기본 폰트 지정, `fontinfo`(.ttf → VectorFont)로 실제 쓰는 폰트를 확정한다.
- **PSB v4 비트맵 폰트**: A8 선형 페이지(swizzle 없음), 글리프 표 + 페이지 이미지. 직렬화기는 원본 6종을 바이트 동일하게 재생성해야
  한다(selftest).
  - v4 체크섬: adler32를 `0x08..0x28` 구간에 대해 계산한 뒤 `0x2C..0x38` 구간까지 이어서 누적한다. v3 체크섬 구현만 있으면 폰트 PSB가 깨진다.
  - chunk_data는 빈 ext 배열 뒤에서 32바이트 정렬이다.
  - 재구성한 names trie는 원본 컴파일러 출력과 바이트가 달라도 된다. 모든 이름의 정방향 조회가 맞는지로 검증한다.
- **글리프 집합**: KS X 1001 한글 2,350자 + 호환 자모 + manifest에 나오는 KS 밖 음절 + 원본에 없는 기호(예: `·` U+00B7).
  검수 수정으로 KS 밖 음절이 새로 생기면 폰트를 다시 빌드한다.
- **크기**: 원본 metric을 유지하고 폰트마다 공통 배율 하나를 쓴다. 작은 아틀라스(8px·12px)에서 한글이 잘리면 잘림이 0이 될 때까지
  그 폰트의 공통 크기를 단계적으로 낮춘다(글자마다 따로 줄이지 않는다).
- **raw TTF**: fontTools로 저장할 때 `recalcBBoxes=False`로 둔다. 기본값이면 원본 glyf가 재인코딩되며 뒤쪽 바이트가 빠진다.
  bbox가 커지면 maxp/head/hhea/vhea를 직접 넓힌다.
- **검증**: 원본 글리프 불변, 픽셀 왕복 일치, 글리프 겹침 0, 전체 가시 코드포인트 × 전 폰트 커버리지, TTF glyf/metric/cmap 오류 0, 렌더 probe 빈 글리프 0.

## 런타임 확인 항목 (미검증)

- 대사 TTF face의 한글과 원본 한자 굵기 차이
- 작은 UI 폰트(8px)의 축소된 한글 가독성
- `·` 표시, 한국어 줄바꿈

- [ ] 무수정 주입 → 재추출 identity 왕복이 전 행 일치
- [ ] 행별 개행 표현(이스케이프/실제 개행) 보존, 재추출 스캐너가 원문 언어로 필터링하지 않음
- [ ] 폰트 PSB 직렬화기 selftest(원본 바이트 동일)와 v4 체크섬 확인
- [ ] 한글 글리프 커버리지·잘림 0·원본 불변·TTF 무손상 검증
- [ ] 한글 표시·줄바꿈·작은 UI 폰트를 런타임에서 확인
