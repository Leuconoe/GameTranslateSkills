# Steam/PC 어댑터 (골격)

> ⚠️ 골격 상태 — 실전 검증 전. 작업 착수 시 `_template/PLATFORM.md` 양식에 따라
> 조사·보강 후 진행하고, 검증된 내용으로 이 문서를 갱신할 것.
> 엔진 노하우(Unity, VN엔진, LucaSystem)는 NSW와 동일하게 `engines/` 모듈을 그대로 사용
> 가능 — 이 어댑터는 추출·적용·시험 방식만 다루면 된다.

## 1. 플랫폼 개요·전제

- 대상: 사용자가 Steam에서 구매한 게임의 설치 폴더
- 특성: 에뮬레이터 불필요 — 직접 실행으로 시험. 파일 접근이 자유로워 난이도 최저.
  단, 게임 업데이트가 패치 파일을 덮어쓸 수 있음. Steam 무결성 검사와의 충돌 고려.

## 2. 도구 체인

| 용도 | 도구 |
|-----|------|
| 추출 | 엔진 모듈 도구 그대로 (Unity: `engines/unity`, VN: `engines/vn-common` 등) |
| 적용 | 파일 교체 또는 엔진별 모드 로더(BepInEx/XUnity.AutoTranslator ⚠️ 미검증) |
| 실행 시험 | 게임 직접 실행 + 로그/캡처 |

## 3. 추출 절차

- 설치 폴더를 작업 폴더 `00_source/`로 **복사**한 뒤 사본에서 추출 (원본 설치 폴더 불변)
- 게임 버전(빌드 ID)을 `SOURCE_INVENTORY.tsv`에 기록

## 4. 빌드/패치 방식

- 기본: 변경 파일만 모은 교체 팩. 가능하면 모드 로더 방식(업데이트 내성)을 우선 검토
- 정적 검사: 교체 파일의 포맷 유효성 + 원본 대비 구조 비교

## 5. 실행 시험

- 패치 적용 → 게임 실행 → 실제 입력·화면 전이·저장 통과 확인, 캡처 보존. emucap은
  Steam 직접 실행을 대체하지 않으며 일반적으로 사용하지 않는다.
- 시험 후 Steam 무결성 검사로 원복 가능함을 INSTALL.md에 안내

## 6. 배포 패키징 규격

- 교체 파일 팩 ZIP (대상 게임 빌드 ID 명시) — 원본 자산의 단순 재배포가 되지 않는
  범위인지 검토 (전체 아카이브 통째 포함 지양, 변경분 최소화)
