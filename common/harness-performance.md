# 하네스 성능·토큰 규칙 (harness-performance)

여러 타이틀을 병렬로 일괄 번역한 배치를 회고해 정리한 규칙이다. 코디네이터와 모든 서브에이전트에 적용하며,
일괄·이어하기 실행에서는 단계 스킬의 일반 규칙보다 우선한다. 품질 게이트(구조 검사·병합·재추출 검증·런타임 QA)는
줄이지 않는다.

## 관측치 (기준선)

| 실행 유형 | 처리량 | 비고 |
|---|---|---|
| 일반 대사 이어하기 | 약 1,100~1,400행 / 100k 토큰 | `RESUME.md`만 읽고 파트 쓰기+다음 slice 읽기 |
| 준비+번역을 한 에이전트에서 | 약 290행 / 100k | 설정·스킬 재독이 컨텍스트 대부분을 차지 |
| 보류 재검토·규칙 변경이 섞인 실행 | 약 860행 / 100k | 이미 번역한 행 재판정 |
| 수천 자짜리 템플릿 공지 행 | 약 120행 / 100k | 행 단위 dupfill로는 거의 줄지 않음 |
| 같은 타이틀에 두 에이전트 | 약 100k 낭비 | 뒤 에이전트가 충돌을 감지하고 아무것도 못 한 채 종료 |
| 세션 재시작·한도 초과 | 진행 중이던 에이전트 6개가 전부 상태 재탐색부터 다시 시작 | 체크포인트가 번역 파트에만 있었음 |

실행마다 `RESUME.md` State 줄에 `행 수 / 사용 토큰`을 남긴다. 한 실행의 처리량이 타이틀 평균의 절반 아래로
떨어지면 다음 실행을 띄우기 전에 원인(긴 행, 재독, 규칙 변경)을 먼저 찾는다.

## 0. 공용 도구 (최상위)

브로커·imagegen 호출·Eden 게시·릴리스 같은 반복 도구는 `skills/game-translate/SKILL.md` "최상위 규칙: 공용 도구만 쓴다"의
공용 도구로만 한다. 타이틀마다 새로 만들거나 복사하면 매 실행이 수만~수십만 토큰을 도구 재작성에 쓴다.

## 1. 번역 전에 고정할 것 (재작업 방지)

번역 뒤에 바뀐 결정은 이미 번역한 수천 행을 다시 읽게 만든다. 가장 큰 누수였다.

- **화자 말투표는 원문 근거로 확정한다.** 첫 일괄 번역 전에 화자×상대 조합별로 원문 어미(반말·정중체)를 세어
  `STYLE.md`와 `RESUME.md`에 넣는다. 코디네이터는 원작 지식만으로 말투 규칙을 지시하지 않는다.
- **보류(HELD) 기준과 산출물 형식**도 첫 chunk 전에 `RESUME.md`에 고정한다. 바꿔야 하면 이미 번역한 행은 소급하지
  않고 리뷰 단계에서 한 번에 처리한다.
- **추출 범위 게이트**: 번역을 시작하기 전에 모든 컨테이너(번들·프리팹·data 파일·실행 코드 리터럴·TextAsset)를 대상으로
  원문 언어 문자를 독립 스캔해 manifest와 대조한다. 늦게 발견된 누락은 감사, 보충 추출, 추가 번역, 도구 회귀 수정으로
  비용이 몇 배가 된다.

## 2. 번역 실행 구조

- **준비 에이전트와 번역 에이전트를 분리한다.** 준비 에이전트가 도구·`RESUME.md`·export까지 끝내고, 번역 에이전트는
  `RESUME.md`와 원문 slice만 읽는다(`glossary-rules.md` "일괄 번역 이어하기 하네스").
- **export 형식은 최소로 한다.** slice에는 `n<TAB>원문`만 둔다. 화자나 장면이 번역에 필요하면 짧은 접두어 하나만 붙이고,
  경로·ID·문맥 열은 넣지 않는다. 출력 파트도 `n<TAB>번역`만 쓰고 원문을 다시 적지 않는다.
- **시리즈 공유 TM을 먼저 만든다.** 같은 시리즈 여러 타이틀을 함께 처리하면 모든 타이틀의 고유 원문을 합친 풀을 만들고,
  공통 원문(UI·데이터 표·시스템 문구)은 한 번만 번역해 나눠 준다. 각 타이틀은 자기 차분만 번역한다. 공통 블록을 번역
  중인 타이틀이 있으면 다른 타이틀은 그 블록을 건너뛰고 최종 dupfill에서 채운다.
  **타이틀 간 TM(`--tm`)·공유 풀을 쓰기 전에 용어집을 먼저 합친다.** 각 타이틀 `glossary.tsv`를 합쳐 개념마다 한국어 하나를
  고르고(예: ガチャ → 가챠/뽑기 중 하나), 고른 표기로 TM 원본 행을 정리한 뒤에 가져온다. 용어가 갈린 채 TM을 쓰면 자매
  타이틀 UI 용어가 섞인다. 고른 표기와 버린 표기는 양쪽 `glossary.tsv`에 기록한다.
- **긴 템플릿 행은 세그먼트 TM**(`glossary-rules.md` 규칙 10)으로 처리한다.
- **큰 타이틀은 비중첩 구간으로 나눈다.** 고유 원문이 수만 행이고 슬롯이 남으면 원문 범위를 고정 분할해 에이전트마다
  다른 파트 접두어(`out/A*`, `out/B*`)를 쓰게 한다(`preflight-checks.md` §6). 병합은 마지막에 한 번 한다.

## 3. 소유권과 중단 대비

- **타이틀(또는 산출물 세트)당 소유자는 하나다.** 에이전트는 시작할 때 `30_translation/.owner`에 라벨과 시작 시각을
  쓰고, 끝나면 지운다. 코디네이터는 새 에이전트를 띄우기 전에 실행 중 목록과 `.owner`를 확인한다. "완료" 알림이 와도
  에이전트의 백그라운드 작업이 남아 있으면 아직 소유 중으로 본다.
- **모든 단계가 체크포인트 한 줄을 남긴다.** 번역뿐 아니라 이미지·리뷰·빌드·런타임 QA도 단계마다 `RESUME.md` State 줄을
  갱신한다(완료한 대상, 다음 대상, 부분 빌드 위치). 재시작한 에이전트는 이 한 줄과 디스크 산출물만 보고 이어 간다.
- 재시작으로 생긴 부분 빌드는 `superseded/`로 옮기고 다시 만든다. 이미 끝난 조판·파트는 다시 만들지 않는다.

## 4. 코디네이터 비용

- **브리프는 파일로 둔다.** 타이틀별 이어하기 브리프를 `30_translation/RESUME.md`(번역)와 단계별 `STATE` 줄로 한 번만
  쓰고, 실행 프롬프트는 경로와 담당 범위 3~5줄만 담는다. 같은 긴 브리프를 실행마다 다시 쓰지 않는다.
- **보고 길이를 제한한다.** 이어하기 번역은 3줄, 단계 완료는 15줄 이내로 쓴다. 표·파일 목록·세부 근거는 WORK_LOG와
  보고서 파일에 남기고 경로만 보고한다.
- **진행 확인은 한 번의 짧은 명령으로 한다.** 파트 파일 수·마지막 갱신 시각·재개 지점 명령만 확인하고, transcript나 긴
  로그는 읽지 않는다.
- **동시 실행 수는 사용량 한도에 맞춘다.** 무거운 단계(이미지·리뷰·런타임 QA)는 동시에 두 개를 넘기지 않는다.
  사용량이 빠르게 줄면 번역 외 단계부터 멈춘다.

## 5. 단계별 절감

- **윤문(im-not-ai)**: 번역투 패턴과 말투 후보에 걸린 행만 대상으로 하고, 검수 서브에이전트는 동시에 두 개까지 둔다.
  대사 전체를 다시 쓰지 않는다.
- **이미지**: 대상 목록과 조판 사양을 표(TSV)로 먼저 만들고 스크립트로 일괄 조판·재인코딩한다. 수치 QA(마스크 밖 변경
  0, 재디코딩 일치)는 전수 검사하고, 이미지를 직접 보는 것은 대표 대조표 10장 이내로 줄인다. 이미지 열람은 토큰이 크다.
- **런타임 QA**: 짧은 범위(부팅, 초반, 주요 UI)만 본다. 캡처는 판정에 필요한 장면만 열람한다.
- **모델 배분**: 추출·dupfill·검사·병합·주입·재추출 검증·인벤토리 같은 기계적 단계는 가벼운 모델 서브에이전트로 돌릴 수
  있다. 번역·윤문·말투 판정은 품질이 높은 모델을 쓴다. 사용자나 프로젝트가 모델을 지정하면 그 지정을 따른다.
- **도구 출력**: 명령 출력은 요약(행 수, 오류 수, 해시)만 내보낸다. 전체 파일을 다시 출력하거나 쓴 파일을 다시 읽지 않는다.
