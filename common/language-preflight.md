# 타이틀 언어·지역판 사전조사

신규 타이틀 작업과 조사 근거가 없는 재개 작업에서는 대량 추출·번역·폰트/이미지 수정·
패치 제작보다 먼저 이 절차를 수행한다. `game-translate`를 거치지 않고 개별 스킬을
호출해도 적용한다. 목적은 공식 한국어 지원 여부와 실제 필요한 작업 범위를 먼저
확정하는 것이다. 언어 조사와 최소 메타데이터 확인은 읽기 전용으로 진행한다.

## 1. 공식 정보 조사

- 인터넷에서 해당 플랫폼의 공식 스토어와 개발사·배급사 제품/지원 페이지를 찾는다.
  정확한 제품명, 플랫폼, 지역, 에디션, 발매/업데이트 버전을 대조하고 URL·확인 날짜를
  기록한다. 비공식 판매처나 파일명만으로 한국어 지원 여부를 확정하지 않는다.
- 지원 언어는 **UI/시스템, 자막/대사, 음성**으로 구분한다. 공식 자료가 구분하지 않은
  항목은 `unknown`으로 남긴다. 한국어 음성이 없다는 이유로 한국어 자막도 없다고
  판단하지 않는다.
- 다른 지역의 제품명과 한국어 지원판도 조사한다. 로고가 비슷하거나 이름이 달라도
  개발사·제품 설명·콘텐츠·공식 지역별 페이지를 대조해 동일 게임의 지역판인지 확인한다.
  Title ID/App ID와 실제 패키지는 따로 기록하고 **서로 다른 게임 수와 지역판 패키지 수**를
  구분한다. 동일 게임이라는 사실은 패치 호환성·파일 공유·삭제 허가를 뜻하지 않는다.

## 2. 보유 입력과 교차 확인

- 공식 정보가 어떤 지역/버전에 해당하는지 보유 입력의 ID·지역·버전과 대조한다.
  NSW에서는 우선 NACP의 지원 언어 플래그, CNMT/업데이트 정보 등 최소 control metadata를
  확인한다. 다른 플랫폼도 해당 어댑터의 언어/제품 메타데이터를 사용한다.
- 필요한 경우에만 최소한의 언어 설정·localization catalog·한글 폰트/리소스를 확인한다.
  적용될 업데이트의 실제 언어 선택 경로를 구분한다. 지원 플래그, 한국어 파일 존재,
  정적 폰트 coverage만으로 게임 전체의 한국어 표시를 검증했다고 주장하지 않는다.
- 일본어/영어 기본값이나 직렬화 필드가 남아 있어도 한국어 테이블로 덮어쓰는지 확인한다.
  fallback, debug, 비활성 UI, 닉네임 기본값을 곧바로 실제 미번역 노출로 세지 않는다.
- 공식 자료와 로컬 정보가 다르거나 해당 버전의 근거가 없으면 `unknown`과 차이·다음
  확인 방법을 기록한다. 한국어 미지원으로 추정하여 번역을 시작하지 않는다. 불확실성에
  의존하는 변경만 보류하고, 출처 조사와 읽기 전용 확인은 계속한다.
- 이 조사를 이유로 에뮬레이터를 새로 실행하거나 기존 runtime 전제·권한을 우회하지 않는다.

## 3. 사용자 안내와 작업 분기

| 조사 결과 | 다음 행동 |
|---|---|
| 보유판의 공식 한국어가 사용자의 한국어 플레이 목적을 충족 | 지원 사실과 언어 설정 방법을 먼저 안내한다. 전체 번역·폰트 교체·이미지 번역을 자동 시작하지 않는다. |
| 다른 지역판/에디션에 공식 한국어가 있음 | 해당 판과 보유판의 차이, 언어 지원 근거를 먼저 안내한다. 이미 한국어 지원판이 있다는 사실을 숨긴 채 보유판 번역으로 직행하지 않는다. |
| 사용자가 공식 한국어의 오류·미번역 보완을 명시적으로 요청함 | 기존 요청 범위만 진행한다. 같은 승인을 다시 묻지 않는다. 실제 노출/consumer와 필요한 변경을 증명하고 공식 번역·폰트·이미지를 보존한다. |
| 공식 한국어가 확인되지만 보완 작업 여부가 불명확 | 한국어 사용 안내로 끝낼지, 구체적 보완을 할지 간단히 확인한다. 응답 전에는 읽기 전용 조사만 계속한다. |
| 공식 한국어 미지원이 근거로 확인됨 | 근거와 대상 언어 슬롯을 기록하고 기존 번역 파이프라인으로 진행한다. |
| 정보 부족·불일치 | 미확인 범위를 보고하고 추가 조사한다. 전제에 의존하는 번역/패치를 보류한다. |

일반적인 “번역해 줘” 요청만으로 공식 한국어판의 전체 재번역이나 모든 fallback 필드의
치환까지 요청받았다고 해석하지 않는다. 사용자가 이미 보완/재번역 범위를 정했다면
그 지시를 적용한다. 이는 작업 범위를 정하는 절차이며 기존 `prepare-only` 검수를
매번 사용자 승인 단계로 바꾸는 규칙이 아니다.

## 4. 기록과 재개

기존 프로젝트의 `30_translation/ANALYSIS.md`에 다음을 기록하고 `PROJECT.md` 및
`HANDOFF.md`에서 그 조사 결과와 결정을 참조한다. 새 루트 파일이나 임의 상태 enum을
만들지 않는다. 프로젝트가 아직 없으면 먼저 조사 결과를 사용자에게 보고하고,
필요한 작업 범위가 정해졌을 때 표준 프로젝트를 만든다.

| 기록 항목 | 내용 |
|---|---|
| 입력 식별 | 제품명·별칭·플랫폼·지역·에디션·ID·본편/업데이트 버전 |
| 공식 근거 | 출처 URL·확인 날짜·해당 지역/버전·UI/자막/음성 언어와 미확인 항목 |
| 지역판 관계 | 동일 게임 여부와 근거, 별도 패키지 ID, 공식 한국어 제공판 |
| 로컬 확인 | 확인한 메타데이터/설정/catalog 경로·관찰, 적용 업데이트, 근거의 한계 |
| 결정 | 전체 번역 / 공식 한국어 사용 안내 / 사용자 지정 보완 / 조사 계속, 사용자 안내 및 기존 지시 |

한국어 사용 안내로 끝난 경우 추출·번역·이미지·폰트·runtime QA를 완료한 것으로 표시하지
않는다. 실제로 진행하는 파이프라인에만 기존 완료 기준과 상태를 적용한다.

같은 입력·버전의 유효한 조사 결과는 재사용한다. 조사 누락, 입력/업데이트/지역 변경,
공식 지원 정보 변경 근거가 있을 때 필요한 부분만 갱신한다. 재개 시 공식 한국어가
뒤늦게 확인되면 사용자에게 알리고 남은 작업 범위를 조정하되 기존 원본·번역·패치·
증거를 자동 삭제하거나 다시 만들지 않는다.
